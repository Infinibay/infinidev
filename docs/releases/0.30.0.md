# Infinidev 0.30.0 — Context continuity and verifiable completion

This release improves continuity during long tasks and makes execution failures
visible in the final task status. It also simplifies the engine's final validation
and correction path while preserving its public interfaces.

## Highlights

- **Retained user guidance.** Instructions received during execution survive Step
  boundaries and checkpoints independently of summaries. Messages arriving during
  final validation defer completion, including guidance forwarded to team workers.
  Attachment references remain durable without persisting image payloads in the
  guidance history.
- **Honest completion states.** Rejected validation, verifier errors, exhausted
  corrections and stopped review rework cannot become successful completion.
  Closing every planned Step prompts an explicit Task decision instead of
  automatically declaring success.
- **Interruptible corrections.** Corrective tools use the engine's foreground
  cancellation scope. Native and manual tool calling preserve their transcript
  contracts, including required reasoning fields and responses for skipped calls.
- **Fresh evidence.** Resumed source observations require revalidation, incremental
  indexing drops stale symbols from deleted files, and corrective edits refresh
  the source context used by the next attempt.
- **Command lifecycle fixes.** Closed output streams stop busy polling without
  disabling timeout or cancellation checks while the process remains alive.
  Incomplete capture tails are not presented as complete output.
- **Practical engineering guidance.** Existing role-specific methods now emphasize
  contract testing, cohesive responsibilities, safe retries and measured performance.
  Specialized capabilities remain opt-in. Conditional instruction blocks are
  included whole or omitted rather than truncated mid-rule.
- **Simpler internals.** A private correction session owns model/tool interaction
  and budgets; the final evaluator owns acceptance policy. The evaluator shrank
  from 253 to 68 lines, with unchanged behavior in differential comparisons.

## Compatibility and packaging

No database migration or new user setting is required. Existing checkpoints use
defaults for newly retained context fields. The legacy string-returning
`apply_guardrail` interface remains available; the engine uses typed outcomes to
distinguish successful completion from partial results.

Python and web package versions are synchronized at 0.30.0. The project lockfile
is refreshed so locked CI installation works again; third-party package versions
are unchanged. Release distributions include the rebuilt web interface and its
third-party notices.

## Validation

- Python suite with the web extra installed: 5501 passed, 12 skipped.
- Frontend: 5 unit tests and 4 browser integration tests passed.
- Frontend build, wheel/source builds and distribution metadata checks passed.
- Guardrail refactor: 648 deterministic before/after scenarios matched; an
  independent review also found no differences in 624 exception/cancellation
  scenarios.

These checks establish tested contracts and packaging. Prompt-guidance changes
have not been measured as a task-success improvement in a new model A/B campaign.
