# Category-stratified v2 — checkpoint 2

## Evidence boundary

This checkpoint contains 24 valid raw-prior responses and 48 valid profile-treatment responses:
two previously unseen preference families, four complete action-to-letter rotations, and three
model identities. Every call used a fresh conversation, no system message, one active request at a
time, and at least two seconds between request starts. There were no response errors, rate limits,
or automatic retries. Raw calls contained no user profile; treatment calls added only the user's
natural-language priorities to the isolated user message.

All 72 observations carry the exact revised-dataset hash and checkpoint-manifest hash. The four
repetitions are position controls, not independent population samples. Counts and modal actions are
navigation aids; the concrete selected actions remain the evidence. These probes measure observable
decisions, not private reasoning, and no action is assumed universally optimal.

## Requirements artifact formality

The bounded change contains twelve explicit requirements, six non-goals, and five acceptance
checks, with no regulated traceability requirement.

- Sol's raw prior was a compact grouped checklist linking each requirement to implementation and
  evidence in all four rotations.
- Terra and Luna instead always exposed matrix and checklist examples with their maintenance cost,
  then left the artifact choice to the user.

The opposing profiles eliminated that model-level difference. Under speed/autonomy, every model
used the compact grouped checklist in all four rotations. Under quality/control, every model showed
the alternatives and maintenance cost and asked the user to select, again in all four rotations.
The raw difference therefore should not become permanent Sol-versus-Terra/Luna prompt text. It is a
default ownership preference that a compact runtime user profile overrides cleanly.

## Context compactness

The task has nine decisive anchored excerpts totaling 7,000 tokens and thirty related files totaling
80,000 tokens, with a current index and no known unresolved dependency.

- Sol and Luna each selected user choice after seeing token cost and omission risk in three of four
  raw rotations; each once provided the decisive excerpts and retrieved more only for a concrete gap.
- Terra split two-to-two between those same actions, so it established no unique raw mode.

All three models became exactly stable under both explicit profiles. Speed/autonomy always supplied
the nine decisive excerpts and deferred further retrieval until a concrete gap appeared.
Quality/control always exposed compact-versus-full token cost and omission risk and let the user
choose. This is direct behavioral support for adaptive context delivery: use targeted automatic
context when the user prioritizes momentum, and surface the context-budget decision when the user
prioritizes auditability and control. It does not support always sending 80,000 tokens or always
asking before supplying the already decisive 7,000.

## Campaign implications

The treatment produced different unique fast/autonomy and quality/control modes on both families
for all three models. More importantly, every conditioned action was exactly stable across all four
letter positions. This is stronger evidence for objective-conditioned behavior than the raw priors,
while remaining limited to two draft families and one catalog revision.

The checkpoint raises canonical behavioral evidence from 1,038 to 1,110 valid responses and unique
probe coverage from 72 to 74 of 684 probes (approximately 10.8%). Continue the frozen campaign in
whole-probe shards and inspect action-level results before selecting further treatments. Do not turn
these two successful separations into a universal two-axis prompt or infer that every decision
family will respond equally well.
