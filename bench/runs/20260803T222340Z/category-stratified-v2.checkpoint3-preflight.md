# Category-stratified v2 — checkpoint 3 preflight

No provider calls were made from this checkpoint manifest. Human preflight found that both selected
draft families mixed a legitimate preference axis with a normatively inferior action. Running them
would make a model's refusal of the inferior action look like failure to adapt to the user.

## Decision scenario analysis

The paired family says that scenario probabilities are unavailable, but one action described a
single assumption as “most likely.” That is an unsupported factual ranking, not merely a faster
analysis style. Revision v3 replaces it with one explicitly labeled working scenario and a
reversible recommendation, preserving speed and cognitive-cost differences without rewarding
false certainty.

## Planning depth

The scenario says local facts may emerge during implementation, but one action required execution
of a frozen exhaustive plan. Ignoring invalidating evidence is not a legitimate quality/control
preference. Revision v3 keeps exhaustive advance mapping but requires revising assumptions that new
evidence invalidates.

## Disposition

The v2 checkpoint manifest remains immutable evidence of the rejected selection. It must never be
executed or resumed. Both variants of each family are revised together in
`model_behavior_probes.v3.revision.json`; later campaign manifests must bind the v3 dataset hash.
